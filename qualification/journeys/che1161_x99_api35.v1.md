## Admission And Positive Attempts

This document does not issue a device grant. Before execution, two fresh independent non-author reviewers must accept this exact candidate revision. Sol must then issue a separate exclusive admission for the exact target class and serial. Old grants remain closed.

Before boot or provider activity, verify the configuration attachment digest and the existing offline-route preflight from the baseline pilot. A missing or mismatched configuration or an unverified route is a stop condition. Do not fall back to the repository default configuration. Record provider-key and fake-mode checks as booleans only.

Run the accepted goal once for `clean_pass`. After that attempt passes and its cleanup/release is verified, run the same goal once more as a separate `clean_rerun`. Use the pinned runner and configuration for both invocations. Use the exact serial from Sol's fresh admission. Generate new distinct UUIDv4 values for `--session-id` and `--run-id` for each invocation. Do not retry an invocation or reuse either identifier.

The baseline invocation shape is:

```bash
timeout --signal=TERM --kill-after=30s 900s uv run artemis run "Open Settings, find Battery and tell me the current level" \
  --profile flash --device-serial "$ADMITTED_SERIAL" --standalone \
  --session-id "$SESSION_ID" --run-id "$RUN_ID"
```

For each positive attempt, require a successful task result that reports the current-charge percentage visible on an identifiable `Settings > Battery` page. Same-attempt privacy-safe screenshot or hierarchy evidence must show that page and its percentage. A status-bar percentage alone is insufficient. Require the attempt and batch reconciliation files to report an accepted single attempt, with the `FlashRunner` usage reconciled to manifest node `operator` as `match` from the same attempt's manifest and native usage records.

## Negative Control

The intended false assertion is that the current-charge percentage on the same attempt's `Settings > Battery` evidence equals `101%`. The control is valid only when the final assertion is classified `fail_assertion` and its process exits nonzero. A provider or infrastructure error is not an assertion failure.

This arm is blocked at the pinned runner. `qualification/tools/checker_verdict_exit.py` is absent from commit `cbf2fea84cbd47ea54053239679ab521b01d4d23`. The helper with that path in the current repository is the CHE-844 Pocket save/relaunch adapter; its package, saved-step, balance, and DataEngine evidence contract is not compatible with system Settings. Do not invoke that helper for this case. No executable command is specified for this arm until a separately reviewed source revision supplies compatible support. Record this arm `BLOCKED_SOURCE_GAP` / `NOT-RUN`, never as a documentation-only pass.

## Evidence And Cleanup

For every executed arm, preserve the exact runner SHA, case and candidate digests, configuration attachment ID and digest, target class, host, freshly admitted serial, fresh session/run IDs, start/end result and process exit status. Preserve the attempt manifest, native `llm_usage` records, both reconciliation outputs when produced, the final assertion evidence, and privacy-safe page evidence. Distinguish assertion failure, infrastructure failure, and unavailable-device coverage.

On every exit, preserve available evidence before cleanup. Stop only recorded run-owned Artemis, emulator, and private-ADB processes. Restore settings changed by the run and verify process and endpoint release. Return cleanup evidence to Sol. If cleanup is unverified, leave the target unavailable with a named recovery owner.
