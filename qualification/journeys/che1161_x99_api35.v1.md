## First-Contact Endpoint And Boot Contract

The pinned standalone CLI loads `ADB_HOST` and `ADB_PORT` into `settings`. Before task execution, `run_command` constructs `AdbClient` from those loaded values and `display_device_status` calls `device_list`. The task config, SDK agent, and driver factory also use those settings. `ADB_SERVER_SOCKET` alone is insufficient: malformed or conflicting socket selection can fall back to loaded settings or the shared default.

Every fresh Sol admission must bind the exact serial and private socket `tcp:127.0.0.1:<port>` together. The port must be a decimal integer from 1 through 65535 and must not be shared-default port `5037`. Before boot or any Artemis command, validate endpoint inputs and loaded configuration without device I/O. Set `ADB_SERVER_SOCKET`, `ADB_HOST=127.0.0.1`, and `ADB_PORT=<same admitted port>` in the standalone CLI process environment; all three and the effective loaded settings must match the fresh admission. Reject missing, malformed, conflicting, or shared-default `tcp:127.0.0.1:5037` selection. Any mismatch stops before boot and before the CLI's first device contact. Keep this binding process-local; do not persist ADB preferences or rely on a later activation log.

The same-invocation endpoint evidence must record the exact selected `ADB_SERVER_SOCKET`, `ADB_HOST`, `ADB_PORT`, and executed Artemis argv in the command receipt before first contact. An admission label alone is insufficient. Keep secret checks boolean-only.

Before each arm, repeat the configuration, loaded-settings, offline-route digest/verdict, clean runner checkout, testcase digest, and endpoint gates. Sol's fresh admission must provide the exact headless boot argv and flags before boot. Luna does not select GPU flags. Record the exact executed boot argv and its result. Within 300 seconds, the exact admitted serial must be online, `sys.boot_completed` must equal `1`, and privacy-safe evidence must confirm unlocked UI. A missing or mismatched boot command or readiness timeout is `failed_or_invalid_no_retry`; do not launch Artemis.

Before each Artemis call, preserve privacy-safe evidence of a clean Settings start state: Settings is closed and Battery is not already open. Exclude unrelated personal content. Generate fresh UUIDv4 values for `--session-id` and `--run-id`; they must differ from each other and every prior attempt. Equal or reused IDs fail closed before boot. Select qualification arms by their `id`, never array position.

For every arm, the claim binds that arm's serial and private endpoint from before boot through verified cleanup and release. The exact admitted serial must reach unlocked UI within 300 seconds of the boot request. It must be online and `sys.boot_completed` must equal `1`. A readiness timeout is `failed_or_invalid_no_retry`; do not launch Artemis.

Run the accepted goal once for `clean_pass`. After the attempt passes and its cleanup/release is verified, acquire a new exclusive admission and repeat every preflight gate before `clean_rerun`. Use the same pinned runner and configuration for both invocations. A released claim grants no authority for a rerun. Do not retry an invocation.

The baseline invocation shape is:

```bash
ADB_HOST=127.0.0.1 ADB_PORT="$ADMITTED_PRIVATE_ADB_PORT" \
  ADB_SERVER_SOCKET="$ADMITTED_PRIVATE_ADB_ENDPOINT" \
  timeout --signal=TERM --kill-after=30s 900s uv run artemis run "Open Settings, find Battery and tell me the current level" \
  --profile flash --device-serial "$ADMITTED_SERIAL" --standalone \
  --session-id "$SESSION_ID" --run-id "$RUN_ID"
```

A status-bar percentage alone is insufficient.
